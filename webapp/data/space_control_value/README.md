# Data pipeline for Space Control &amp; Value data
This folder contains all scripts to import the Space Control &amp; Value data into the Supabase PostgreSQL database, plus the player name mapping file.

---

## Files

### `build_mapping.py`
**Purpose:** Generates `sc_player_mapping.json` — a pre-computed look-up table that maps every StatsBomb player name to its corresponding Transfermarkt `player_id` in the database.

**Why it exists:** The two datasets use different name conventions (e.g. StatsBomb: `"Aurélien Djani Tchouaméni"`, Transfermarkt: `"Aurélien Tchouaméni"`) and different team names (StatsBomb: `"Turkey"` / `"Czech Republic"`, Transfermarkt: `"Turkiye"` / `"Czechia"`). A direct SQL join on `player_name` would miss ~40% of players.

**Matching strategy (in order of priority):**
1. **Exact match** — name + team alias match directly
2. **Manual overrides** — hardcoded corrections for nicknames (Pedri, Rodri, Jorginho, Pepe, Vitinha, Dani Olmo, etc.)
3. **Token overlap** — picks the DB player on the same team that shares the most name tokens

**Run once before `import_space_control.py`:**
```bash
python build_mapping.py
# Output: sc_player_mapping.json  (272/272 matched, 0 unmatched)
```

---

### `sc_player_mapping.json`
**Purpose:** Pre-built mapping generated by `build_mapping.py`. Contains one entry per player:
```json
{ "sc_player": "Daniel Olmo Carvajal", "sc_team": "Spain", "db_player_id": "293385" }
```
`db_player_id` is the Transfermarkt `player_id` used to JOIN with `player_profiles` in the backend. If `null`, the player is not in the Transfermarkt database (no player from the current 272 should be null).

**Do not edit manually** — regenerate with `build_mapping.py` if the source CSVs change.

---

### `import_space_control.py`
**Purpose:** Imports the two Space Control CSVs into Supabase, creating `sc_indices` and `sc_aggregated` tables.

**What it does:**
1. Reads `sc_player_mapping.json` to resolve `db_player_id` for each player
2. Creates (or updates) the `sc_indices` table — one row per player, contains the 4 composite indices and all 13 `pct__` percentile columns used by the radar plots
3. Creates (or updates) the `sc_aggregated` table — one row per player, contains the raw/per90/percentage "mother stats" shown under each radar
4. Uses `ON CONFLICT (player, team) DO UPDATE` so re-running is safe (idempotent upsert)
5. Runs `ALTER TABLE sc_indices ADD COLUMN IF NOT EXISTS db_player_id` to handle tables created without that column

**Run order:**
```bash
# 1. Generate the mapping (only needed once, or when source CSVs change)
python build_mapping.py

# 2. Import into Supabase
python import_space_control.py
# reads SUPABASE_DB_URL or DATABASE_URL from webapp/backend/.env
# or pass explicitly:
python import_space_control.py --db-url "postgresql://..."

# 3. Dry run to validate files without touching the DB
python import_space_control.py --dry-run
```

**Source files (read-only, not copied):**
- `../../H1_Space_Control_and_Value/data/player_space_control_indices.csv`
- `../../H1_Space_Control_and_Value/data/player_space_control_aggregated.csv`

**DB tables created:**

| Table | Rows | Key columns |
|---|---|---|
| `sc_indices` | 272 | `player`, `team`, `db_player_id`, `macro_role`, `idx__*`, `pct__*` |
| `sc_aggregated` | 272 | `player`, `team`, raw + per90 + pct mother stats per dimension |

---

### `supabase_importer.py`
**Purpose:** Imports the main Transfermarkt player database (player profiles, totals, teams, match logs). This is the pre-existing importer — run it first, before the space-control importer.

---

## Full setup order (fresh database)

```bash
# 1. Import main player database
python supabase_importer.py

# 2. Generate space-control mapping
python build_mapping.py

# 3. Import space-control tables
python import_space_control.py
```

After these three steps the backend has all the data it needs to serve all 272 players with full stats + space-control indices.
